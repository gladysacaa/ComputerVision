Notebook 2: Preprocessing and Train/Val/Test Split

## Overview
This notebook is designed to preprocess image frames extracted from videos for a vision project. It handles resizing, dataset splitting into train, validation, and test sets, and computes per-frame brightness and lighting categories. The processed data and metadata are saved for subsequent model training.

## Setup
Before running this notebook, ensure you have:
1.  **Mounted Google Drive**: The notebook expects access to your Google Drive for input and output directories.
2.  **Extracted Images**: The `EXTRACTED_FOLDER` variable (default: `/content/drive/MyDrive/VisionProject/Extracted_Images`) should contain subfolders, where each subfolder represents a class and contains image frames (JPG or PNG).

## Preprocessing Steps
1.  **Initialization**: Defines essential paths, a base resizing dimension (384x384), a random seed for reproducibility, and train/validation split ratios (70%/15%).
2.  **Frame Resizing and Splitting**: Iterates through each class folder, resizes all images to 384x384 (maintaining color information), and splits them into training, validation, and test sets according to the defined ratios. Images are saved into respective `processed/train`, `processed/val`, and `processed/test` directories.
3.  **Metadata Generation**: For each processed frame, its brightness (mean grayscale value) and an assigned lighting category (shadowed, well_lit, bright, overexposed) are computed and stored in `frame_metadata.csv`.
4.  **Split Summary**: A summary of the number of images per class in each split is saved to `splits_summary.csv`.

## Outputs
-   `processed/train`, `processed/val`, `processed/test`: Directories containing the resized images, organized by class and split.
-   `frame_metadata.csv`: A CSV file detailing each processed image's filename, split, class, brightness mean, and lighting category.
-   `splits_summary.csv`: A CSV file summarizing the number of images for each class across the train, validation, and test splits.

## Verification
The notebook includes sections to verify the dataset split and inspect the lighting distribution across the different splits to ensure data integrity and balance.

Notebook 3

This project involves training a MobileNetV2 model for image classification at different resolutions (64, 128, 224, 384). The goal is to compare the performance metrics, training time, and model size across these resolutions to identify the optimal configuration.

The notebook `3_train_mobilenet.ipynb` is executed four times, once for each target resolution. It performs the following steps:
1. Loads preprocessed images.
2. Resizes images on-the-fly to the `TARGET_RESOLUTION`.
3. Trains MobileNetV2 with ImageNet-pretrained weights.
4. Evaluates the model on the test set.
5. Records training time, accuracy, F1 score, and GPU memory usage.
6. Saves the trained model and metrics to a resolution-specific results folder.

## Setup and Installation

To run this project, ensure you have the following:

1.  **Google Colab Environment**: This notebook is designed to run in Google Colab.
2.  **Google Drive Access**: The project requires access to Google Drive to load preprocessed data and save results. Ensure your Google Drive is mounted.
3.  **Dependencies**: All necessary libraries are imported within the notebook, primarily `tensorflow`, `numpy`, `pandas`, `sklearn`, and `matplotlib`.

## Usage

2.  **Mount Google Drive**: Execute the cell in section 3.1 to mount your Google Drive.

This notebook analyzes and compares the performance of a vision model when trained and evaluated with different input resolutions. The primary goal is to understand the trade-offs between model accuracy, training time, and inference time as the input resolution changes.

### Key Findings:

*   **Resolution vs. Accuracy/F1**: The notebook visualizes how test accuracy and Macro F1 scores vary with input resolution, identifying resolutions that yield better performance metrics.
*   **Resolution vs. Training/Inference Time**: It also plots the relationship between input resolution and computational costs, specifically training time per epoch and inference time per image.
*   **Accuracy vs. Compute Trade-off**: A dedicated plot illustrates the trade-off between test accuracy and inference cost, helping to identify potential 'sweet spots' for deployment.
*   **Per-Class F1 Analysis**: The performance is broken down by individual classes, showing per-class F1 scores at different resolutions to understand class-specific impacts.
*   **Interpretation Helper**: The notebook includes an automated interpretation section that identifies the resolution achieving the best accuracy and suggests the smallest resolution that maintains accuracy within a 2 percentage point (pp) margin of the best, along with the associated inference speedup.
